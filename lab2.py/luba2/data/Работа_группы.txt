ЛР2 «Умный поиск по документам» — вариант 2 «Астрономический атлас»

Запуск через терминал командой: python data/p6_main.py data

1.  — p1_load.py
  Загрузку текстов в память компьютера.
  load: Открывает CSV-файлы с помощью библиотеки pandas. Параметр utf-8-sig спасает от сломанной русской кодировки Windows, 
  on_bad_lines='skip' игнорирует случайные пустые строки, из-за которых программа раньше падала.
  explore: Проводит разведку данных. Она выводит на экран общую статистику: сколько всего документов (360) и запросов (30), 
  проверяет, нет ли пустых полей, считает среднюю длину текста и проверяет уникальность ID, чтобы записи не дублировались.

2. Арканова Ксения — p2_text.py
  Нормализация текста.
  words: Приводит всё к нижнему регистру, заменяет «ё» на «е» и убирает знаки препинания, оставляя чистые токены (слова).
  stem и make_lem: Приводят слова к их начальной форме. Так как pymorphy3 не скачался из-за интернета, 
  сработал встроенный «умный стеммер» — он просто отрезает известные окончания (например, превращает «наблюдениями» в «наблюден»).
  STOP: Список «мусорных» слов (и, в, во, на, ищу, хочу), которые не несут глубокого смысла и только путают поиск. Они отсекаются.
  full_text: Склеивает заголовок документа и его текст в одну строку, чтобы поиск шел сразу по всей карточке.

3. Мендогралова Софья — p3_base.py
  Базовый поиск.
  base_search: Переводит слова запроса и документа во множества (set) и просто считает, 
  сколько общих слов совпало. У кого совпадений больше — тот и выше в выдаче.
  Минусы: Не понимает важность слов. Если в запросе есть редкое слово «Энцелад» и частое слово «наблюдение», 
  базовый поиск посчитает их одинаково ценными, из-за чего выдаст плохой результат.

4. Корсеева Доминика — p4_tfidf.py
  Умный поиск TF-IDF.
  Класс Engine:
	• TF (Частота слова): Считает, как часто слово встречается в конкретном документе.
	• IDF (Обратная частота): Штрафует популярные слова (например, «космический» или «обзор») 
  и дает огромный приоритет редким словам (например, «Альтаир»). Если редкое слово совпало — документ мгновенно взлетает вверх.
  search: Превращает документы и поисковый запрос в векторы (наборы чисел) и считает косинусное сходство (cosine_similarity). 
  Простыми словами: она измеряет угол между вектором запроса и векторами документов в многомерном пространстве. 
  Чем меньше угол — тем ближе документы по смыслу.

5. Фролов Павел — p5_compare.py
  Валидация и сравнение.
  Словарь CONF: Содержит 4 разные настройки для TF-IDF (A, B, C, D), чтобы проверить, как влияют стемминг, 
  удаление стоп-слов и добавление пар слов (биграмм) на результат.
  metrics и base_metrics: Берут 8 открытых запросов, прогоняют их через поисковики и сравнивают с эталоном из файла разметки (dev_relevance.csv). 
  Они считают:
	• Hit@5: Нашелся ли правильный документ вообще в первой пятерке выдачи (1 — да, 0 — нет).
	• MRR@5: На каком именно месте оказался правильный документ. Если на первом — отлично (1.0), 
  если на втором — хуже (0.5), если на третьем — (0.33).

6. Богданова Владислава — p6_main.py + ВЫВОДЫ.txt
  Главный скрипт запуска.
  Диспетчер, который управляет всем процессом от начала до конца.
  Собирает все модули вместе.
  Запускает загрузку, предобработку, поиск и расчёт метрик.
  Выводит красивую итоговую таблицу в консоль (ту, где победила конфигурация B).
  Автоматически вызывает функцию draw для построения графика metrics.png.
  Сохраняет финальные предсказания для всех 30 запросов в файл search_results.csv и записывает все сложные случаи в errors.csv.

Связка: p1 -> p2 -> p3 / p4 -> p5 -> p6.  Все файлы лежат в одной папке.

*установка виртуального окружения venv через терминал
1. python -m venv venv
2. windows (PowerShell): .\venv\Scripts\Activate.ps1
   macOS / Linux:        source venv/bin/activate
3. pip install -r requirements.txt
4. запуск: python data/p6_main.py data

*requirements.txt — текстовый файл, в котором прописаны библиотеки (pandas, scikit-learn, matplotlib, numpy).
